GCEstimjmv v1.1.1 maintenance release review
Date: 2026-10-28
Status: implemented, tested, compiled and installed locally; unpublished.

1. ROOT CAUSES AND CORRECTIONS

Duplicate colours: Ridge Trace requested six palette entries and recycled them.
The Ridge adapter now passes the complete, deterministically sorted internal
coefficient universe to the existing .gceTermColours() helper. Foreground-only
legacy theme arguments that are too short fall back to jamovi's categorical
palette. Scales are applied after the jamovi theme, retaining stable mappings
across coefficient plots, filtering, intercept hiding and coefficient reordering.

Rejected displayed names: the previous filter compared text only with model
matrix identifiers, which retain formula backticks. .gceRTResolveTerms() now
maps both displayed labels and complete internal identifiers to internal keys.
The shared collision-safe label map retains factor-level suffixes. Matches are
combined across both namespaces; names identifying multiple coefficients are
rejected as ambiguous rather than guessed. Errors list valid displayed labels
and explain the comma/quote convention. Parsing warnings become one rejection.
Validation occurs after model-matrix construction, before fitting and plots.
Current image states store resolved terms; old image states retain a fallback.

Missing/blank plots: build failures formerly cleared image state and hid the
image; rendering failures were swallowed and returned FALSE. Requested images
now retain state and visibility and receive an image-level error with their
user-visible title. Unexpected render errors set the image error and propagate
with that title. Successful later builds reset result status. No per-plot
coefficient-input warnings are emitted.

Installed jmvcore 2.7.38 was inspected directly: reject() calls stop(createError())
and stops the analysis run; it is not a result-local rejection API. Invalid
filters therefore produce one analysis-level rejection, which jamovi displays
until corrected. This may temporarily leave requested image areas unrendered;
the backend does not hide them. Unexpected build failures instead use
ResultsElement$setError(), preserving unaffected results. The catch in
.gceRTRender() adds result context and rethrows rather than suppressing errors.

3. SHARED HELPERS

R/plot-state.R was not changed. Its .gceCoefficientLabels() implementation was
verified equivalent to the old Ridge implementation, including make.unique()
collision handling. Production tables and plots now call it directly; the old
.gceRTLabels() name remains as a thin compatibility adapter. .gceRTColours()
retains only Ridge ordering/theme adaptation and delegates palette generation
to .gceTermColours(). No unrelated plot palette was changed.

5. COEFFICIENT FILTER VERIFICATION

Passing tests cover displayed labels, internal names, non-syntactic names,
spaces, factor levels and suffixes, quoted commas, unknown/ambiguous input,
collision-safe labels and valid-label error messages. Filtering changes neither
coefficient table calculations nor model-matrix names. Ambiguity across a
display label and a different internal identifier is intentionally rejected;
an unambiguous complete identifier can be used instead.

Live GUI checks accepted X005B and the displayed label "Signal, two" in a
quoted filter. The latter was tested in an isolated copy of the bundled example
with X002 renamed, using a fresh fit. Its legend displayed Signal, two.

6. ERROR HANDLING VERIFICATION

Build failures retain the failed image's state and error status. Rendering
failures no longer silently return an empty image.
